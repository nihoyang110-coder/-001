# 新闻溯源与事实核查

目标不是写一篇读后感，而是回答三件事：**这条消息最早从哪来、哪些部分站得住、我们因此往事实清单里新增或更新了什么**。新闻会过时，事实清单会越积越厚——每次核查都要让清单变得更有用。

## 0. 定位事实库
在工作目录里找 `FactCheck/事实清单.md`。
- 找到：这就是 vault 根目录，之后所有文件都写在 `FactCheck/` 下。
- 找不到：用 `assets/` 里的模板新建 `FactCheck/`（README、事实清单、Templates、Facts、Notes）。
- 没有文件系统（如纯聊天环境）：照常完成核查，最后把新闻笔记和事实卡片以 markdown 代码块输出，方便用户粘贴进 Obsidian。

动手前先运行 `python scripts/factdb.py search <关键词>`（在 vault 父目录下执行，或用 `--vault` 指定路径），看看清单里是否已有相关卡片。已有的结论是本次核查的起点，不要从零重查已证实的东西，而要检查它是否过时。

## 1. 读截图，拆成原子命题
从截图/链接提取：标题、发布者、发布时间、是“原创”还是编译转述。
然后**先拆命题再搜索**——一个标题往往塞了好几个命题，每个命题证据不同。例如“成立18个月，ARR突破10亿美元，20美元AI轻应用必死”是三个命题：时间起点、收入数字及口径、一个观点。
给每个命题标类型：事实 / 数字 / 观点 / 预测。观点和预测不能“证实”，只能澄清“谁说的、原话是什么、被放大了没有”，预测要定一个回看日期。

## 2. 搜索：5–10 次，角度不重复
按 `references/search-angles.md` 的角度矩阵挑角度，每个角度一次，每次都记录到搜索日志。
“不重复”的标准是**带来了新信息或新来源**，不是换个措辞。如果一次搜索的结果全是已见过的域名和说法，把它记为“重复”，换一个角度补搜，直到有 ≥5 次有效搜索。目标 5–10 次有效搜索；网页抓取被拦截、只能靠搜索摘要交叉印证时，总次数可放宽到 15 次，超过 10 次要在日志里写明为什么需要。
必须覆盖：原始来源、当事方自述、至少一个反方/质疑来源、数字口径。

抓取网页失败（被拦截/付费墙）时，在日志里如实写明，并把相关结论的置信度下调一级——依据只有搜索摘要时，不要假装读过全文。

给每个来源标级别：
- **一手**：当事方原话、官方公告、监管文件、原始数据、播客原声
- **二手**：引用一手的主流媒体
- **三手**：转述二手的博客、公众号、营销文
两个来源若引用同一个一手源，只算一个独立来源。

## 3. 溯源链
画出 原始源 → 各级转述 → 用户看到的版本，标出每一跳**措辞怎么变了**（run rate 变 ARR、“从$1M起18个月”变“成立18个月”、“我们不打这个市场”变“必死”）。措辞漂移往往就是这条新闻最大的问题。

## 4. 拆解 → 先立后破
1. 写出主观点和每条支撑依据。
2. **先替它说话（steelman）**：用最强的方式陈述这个观点，避免攻击稻草人。
3. **再红队攻击**：逐条找漏洞——口径偷换、起点偷换、收入≠利润、幸存者偏差、利益相关（说话者是否在为自己融资/卖货）、自相矛盾、无法溯源的“幽灵数字”、时间窗口挑选、**旧闻翻新**（导语沿用几个月前的旧稿，把旧事件写成新事件——查事件本身发生的日期，不只看报道日期）、**范围放大**（“关闭博物馆”写成“关闭科学院”、“点名一人”写成“施压共和党”）。每个攻击点给判断：成立 / 部分成立 / 存疑 / 不成立。
4. 针对成立或存疑的攻击点去找补充证据（可以占用上面的搜索次数）。

## 5. 结论
每个原子命题一行：结论、状态、置信度、一句理由。最后用一句话回答“最开始的说法对不对”和“我们验证了什么”。
再写一段**白话版**：假设读者完全不懂行，用生活化的比喻解释这家公司做什么、数字怎么算的、观点原意是什么、被怎么放大了。

## 6. 落入事实清单（最重要的一步）
每个原子命题对应一张事实卡片，格式见 `references/vault-format.md`。
- 用 `python scripts/factdb.py search` 查重：已有卡片就**更新**它（改 status / confidence / last_checked，在“更新记录”追加一行，news 列表加上本篇），不要建重复卡。
- 没有就用 `python scripts/factdb.py next-id` 拿下一个编号新建。
- 数字类卡片写清口径和时间点（“2026-09 自称年化运行率”而不是“ARR 10亿”），因为数字会变。
- 预测类卡片填 `review_by`，到期回看。
- 和其他新闻的卡片有因果或同源关系时（例如同一场危机引出两条新闻），在两张卡片里都加 `## 关联` 互相链接——事实清单的价值就在于把分散的新闻连起来。
- 全部写完后运行 `python scripts/factdb.py rebuild` 重新生成 `事实清单.md` 的静态表格。

新闻笔记写到 `FactCheck/Notes/YYYY-MM-DD-关键词.md`，结构见 `assets/新闻溯源模板.md`；笔记里引用卡片用 `[[F-xxxx]]`，不在笔记里重复卡片内容。

## 7. 给用户的回复
简短：一张“命题 | 结论 | 置信度”表、最有力的 2–3 个攻击点、白话一句话、新增/更新了哪些卡片、局限（哪些页面没打开、还缺什么证据），并附上来源链接。
如果在 git 仓库里，提交改动；推送失败就如实说明。

## 批量模式（多条新闻并行）
多个核查同时进行时，各自直接写 Facts/ 会撞编号。此时每条新闻只写到 `FactCheck/_staging/<英文短名>/`：
- 新卡片命名 `TMP-01.md`、`TMP-02.md`…，frontmatter `id: TMP-01`，互相引用写 `[[TMP-01]]`；引用已有卡片照常写 `[[F-xxxx]]`
- 新闻笔记 `YYYY-MM-DD-关键词.md` 也放在同一目录
- 想修改已有卡片时，不要直接改，写进同目录的 `updates.md`（卡片号 + 要改什么 + 依据），由汇总者处理
全部完成后由汇总者运行 `python scripts/factdb.py import FactCheck/_staging/*/`，统一编号并重建清单。

## 模式
- 用户说“快速看一下”：3–5 次搜索，只做命题拆分、溯源链和结论，仍然要落卡片。
- 默认：完整流程。
