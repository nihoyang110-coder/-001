# Vault 格式

```
FactCheck/
├── README.md
├── 事实清单.md          # 总表（Dataview 自动表 + 脚本生成的静态表）
├── 别名表.md            # 检索同义词（Meta=Facebook 等）
├── Facts/F-xxxx.md      # 一个命题一张卡（语义层：事实）
├── Entities/名称.md     # 实体页：常见公司/产品的档案（汇总层）
├── Notes/YYYY-MM-DD-关键词.md   # 每次核查的经过（情景层）
└── Templates/
```

## 事实卡片 frontmatter
```yaml
id: F-0005
type: 数字          # 事实 / 数字 / 观点 / 预测
claim: "2026年9月 Higgsfield 宣称年化收入运行率突破10亿美元"
status: 公司自述     # 见下表
confidence: 中       # 高 / 中高 / 中 / 低
subject: Higgsfield  # 公司/人物/行业，便于聚合
first_seen: 2026-10-03
as_of: 2026-09       # 事实成立/数据截至时间（不是核查时间）；无明确时间就填首次核查日
last_checked: 2026-10-03   # 我们最近一次核实的日期
review_by:           # 预测类必填：到期回看日期
supersedes:          # 可选：本卡取代的旧卡
superseded_by:       # 可选：取代本卡的新卡（由 factdb supersede 自动填写）
sources: [一手：官方博客, 二手：TechCrunch]
news: ["[[2026-10-03-xxx]]"]
tags: [fact, Higgsfield]
value: 无用        # 可选：用户判定没价值时填写；不跟进、不用于发布，检索时会标出
```
正文：`## 证据`（支持/反驳）、`## 口径/注意`、`## 更新记录`（每次改动追加一行日期+原因）。

## status 取值
| status | 含义 | 引用规则 |
|---|---|---|
| 已证实 | ≥2 个独立可靠来源一致 | 可直接引用 |
| 公司自述 | 只有当事方说 | 必须写“据公司称” |
| 部分属实 | 核心对，细节/口径有问题 | 带注释引用 |
| 存疑 | 找不到原始来源或互相矛盾 | 不引用 |
| 证伪 | 有证据证明错误 | 作反例 |
| 观点 | 某人的判断 | 写明“谁认为” |
| 待验证 | 预测，尚未到期 | 写明到期日 |
| 已过时 | 曾经成立，已被新卡取代（见 superseded_by） | 不再引用，改引新卡 |

## 命题写法
- 可证伪、带主语、带时间点：好 “2026-08 Higgsfield 披露年化收入7亿美元”；差 “Higgsfield 收入很高”。
- 被证伪的说法也建卡，claim 写原说法并加引号，status=证伪——下次再见到能秒判。


## 记忆分层与更新规则（2026-10-19 起）
| 层 | 放在哪 | 存什么 |
|---|---|---|
| 规则 | 技能文件、platforms.md | 怎么核查、怎么发布、合规红线 |
| 实体 | `Entities/` | 常见公司/产品的一页档案：一句话、关键事实、时间线、注意事项 |
| 事实 | `Facts/` | 一个可验证命题一张卡 |
| 经过 | `Notes/` | 每次核查的截图信息、搜索日志、攻击点 |

- **记什么**：只给“会再遇到、能复用”的命题建卡；零碎细节留在笔记。用户判定没用的标 `value: 无用`。
- **新旧冲突**：新事实推翻旧事实时，**新建卡片**，再运行 `factdb.py supersede 旧ID 新ID 原因`：旧卡标“已过时”并指向新卡，保留历史，不删除。只是补充细节、置信度变化时，直接更新原卡并写更新记录。
- **两个时间**：`as_of` 是事实成立的时间，`last_checked` 是我们核实的时间。引用数字时写“截至 as_of”。
- **检索**：`factdb.py search` 自动按 `别名表.md` 和实体页 `aliases` 扩展同义词；新出现的常用别名随手加进别名表。
- **实体页**：手写“一句话/关键事实/时间线/判断”，“相关卡片”区由 `factdb.py entities` 生成。某公司卡片超过约 8 张时建实体页。
- **保持关注**：用户说“保持关注/盯着”时，把事项加进 `FactCheck/关注清单.md`（盯什么、相关卡片），每周回看任务会检查。
- **定期回看**：`factdb.py due --days 7` 列出 7 天内到期的预测卡和 90 天未核实的数字卡；每周由定时任务自动跑一次。
