# 手表录音 App 任务书（可用版）

## 0. 一句话
Apple Watch 上**随时一键开关**的录音，**体积尽量小**、**不丢录音**；录音传到 iPhone 后**在手机上转文字**，可搜索、可分辨说话人、可导出到 Obsidian。

## 1. 范围
**要做**
- 手动开始/停止录音（多种开关入口），不做全天自动录音
- 录音参数全部可调（采样率、编码、码率、分段、静音跳过）
- 分段录制、打断后自动续录、崩溃后找回
- 自动同步到 iPhone，手机端转写、分说话人、时间线、搜索、导出
- 可选：AI 摘要（用户自己填大模型接口密钥）

**不做**
- 全天自动录音
- 手表上转文字
- 自建服务器（全部本地处理，同 Auday 做法）

## 2. 吸取的开源做法
| 来源 | 许可证 | 借鉴什么 | 用法 |
|---|---|---|---|
| Omi（BasedHardware/omi） | MIT | 16kHz 单声道 + **Opus 编码**；**语音检测门（VAD gate）**，没人说话不传不存 | 可参考代码 |
| Stealth Whisper（AIDEN0602） | **无许可证** | ① **孤儿录音找回**：App 被杀或崩溃后，启动时扫描未传完的文件重新发送；② 发送前查系统传输队列去重；③ 被打断的 m4a 文件缺索引无法播放，但仍保留不删 | **只借思路，不复制代码** |
| woods-whisper（laffan） | **无许可证** | 手表只录音、模型全放手机；手机端转写后再用小模型整理文字 | 只借思路 |
| WhisperKit（argmaxinc） | MIT | 手机端 Whisper 转写（中文可用），多档模型 | 直接集成 |
| FluidAudio（FluidInference） | Apache-2.0 | 手机端语音检测、**说话人分离**（pyannote）、Parakeet 转写（Parakeet 主要是英语和欧洲语言，中文用 Whisper） | 直接集成 |
| watch-transcriber（heyflorin） | MIT | 转写结果按说话人整理，投递到 Apple 备忘录/Obsidian | 参考输出格式 |
| Auday（闭源产品） | — | 无服务器、本地处理；AI 走用户自己的密钥；时间线 + 每日回顾 | 产品思路 |
| 苹果 Siri Recap | — | 只给摘要、7 天删除 | 我们做**逐字稿 + 长期搜索 + 导出**来区分 |

## 3. 功能需求

### 3.1 开关录音（核心体验）
| 入口 | 要求 |
|---|---|
| 手表 App 主界面大按钮 | 点一下开始，再点停止 |
| 表盘复杂功能（Complication） | 一点即开始录，表盘上显示录音中状态 |
| 智能叠放小组件（Smart Stack） | 同上 |
| Ultra 操作按钮（Action Button） | 按一下开始/停止（需验证 API，见 §7） |
| iPhone App | 远程开始/停止手表录音 |
| 反馈 | 开始、停止各一次震动；录音中屏幕显示红点和时长 |
| 自动停止（可选） | 连续 N 分钟没人说话自动停止（N 可设：关 / 10 / 30 / 60 分钟） |
| 单次最长时长（可选） | 关 / 1 / 2 / 4 小时，到时提醒或自动停止 |

### 3.2 录音参数（全部保留，可在设置里改）
| 参数 | 可选值 | 默认 |
|---|---|---|
| 采样率 | 8k / 12k / **16k** / 22.05k / 24k / 44.1k / 48k Hz | **16 kHz**（人声足够，转写模型也用 16k） |
| 声道 | 单声道（固定） | 单声道 |
| 编码 | **Opus** / AAC-HE / AAC-LC / 无损（ALAC，仅调试） | Opus（若手表不支持则 AAC-HE，见 §7） |
| 码率 | 8 / 12 / **16** / 24 / 32 / 48 / 64 kbps | Opus 16 kbps；AAC-HE 24 kbps |
| 分段长度 | 1 / **2** / 5 / 10 分钟 | 2 分钟 |
| 静音跳过 | 开 / 关；阈值（-30 ～ -60 dBFS）；静音多久算安静（1–10 秒） | 开；-45 dBFS；3 秒 |
| 静音保留首尾 | 0 / 0.5 / 1 秒 | 0.5 秒（避免切掉字头字尾） |
| 预设 | 极省（12k/Opus 12k）/ 标准（16k/Opus 16k）/ 高质（24k/AAC 32k） | 标准 |

### 3.3 存储目标（按码率估算，开静音跳过会更小）
| 设置 | 每小时 | 录 4 小时 |
|---|---|---|
| Opus 12 kbps | 约 5.4 MB | 约 22 MB |
| **Opus 16 kbps（默认）** | **约 7.2 MB** | **约 29 MB** |
| AAC-HE 24 kbps | 约 10.8 MB | 约 43 MB |
| AAC-LC 32 kbps | 约 14.4 MB | 约 58 MB |
| 参考：现有开源项目 AAC 64 kbps | 约 28.8 MB | 约 115 MB |

手表端规则：剩余空间 < 200 MB 时提醒，< 50 MB 时停止新录音；**手机确认收到并校验通过后**才删除手表上的分段（可设“手表保留 1 天”）。

### 3.4 不丢录音
1. **分段写入**：每段一个文件，段与段无缝衔接（同一音频引擎连续采集，只换输出文件），每段记录开始/结束时间
2. **抗中断格式**：分段使用写到一半也能读的容器（候选：CAF、Ogg/Opus 流；不用写完才生成索引的 m4a）
3. **打断续录**：来电、Siri、其他 App 抢占音频时，记录“中断”标记，结束后自动恢复录音
4. **崩溃找回**：App 每次启动扫描“待发送”文件夹，把未发送、未在系统传输队列里的分段重新排队
5. **状态持久化**：录音会话信息（开始时间、已完成分段、参数）实时写盘，崩溃后能接上
6. 手表进入低电量模式时：提示用户，继续录音但暂停同步

### 3.5 同步
- 用 WatchConnectivity 文件传输，**录音过程中每段完成就排队发送**（不等全部结束）
- 发送前查系统传输队列，避免重复
- 每段带元数据：会话 ID、段序号、开始/结束时间、参数、校验值
- 手机收到后校验，回执给手表，手表才删除
- 手表与手机断开时本地排队，重连后续传

### 3.6 手机端（iPhone）
| 功能 | 要求 |
|---|---|
| 拼接 | 按会话和段序号还原完整时间线，中断处显示标记 |
| 语音检测 | 二次检测，去掉剩余静音（FluidAudio） |
| 转文字 | 引擎可选：WhisperKit（模型档位可选，中文主力）；Parakeet（英语）；苹果系统语音识别（需验证中文效果）；转写在后台、充电时优先 |
| 说话人分离 | FluidAudio pyannote 流程；说话人可改名，跨会话记住常见说话人（需验证） |
| 时间线 | 按天显示：每次录音的时长、说话人、关键句；点文字跳到对应音频位置播放 |
| 搜索 | 全文搜索（先做关键词，后续可加语义搜索） |
| 导出 | Markdown（带时间戳和说话人）→ 文件 App / Obsidian 库；音频导出 m4a；分享 |
| AI 摘要（可选） | 用户填自己的大模型接口密钥；默认关闭；只发文字不发音频 |
| 删除 | 单条删除、按日期批量删除、自动清理（关 / 30 / 90 天删音频保留文字） |

### 3.7 隐私与合规
- 全部本地存储，开启系统数据保护（锁屏加密）
- 录音时手表屏幕常显红点，提醒自己也让旁人可见
- 首次使用提示：录音前告知对方；不同地区对录音有不同法律要求
- 不接任何统计、广告 SDK；iCloud 备份由用户选择

## 4. 非功能指标
| 项目 | 目标 |
|---|---|
| 开始录音响应 | 从点击到开始采集 < 1 秒 |
| 丢失上限 | 任何异常（崩溃、强杀、断电前）最多丢当前分段 |
| 存储 | 默认设置每小时 ≤ 8 MB（不含静音跳过） |
| 耗电 | 实测并记录：每小时录音耗电 %（各机型），目标在设置页显示估算可录时长 |
| 转写速度 | iPhone 15 及以上，1 小时录音在充电时 10 分钟内转完（WhisperKit 中档模型，需实测调整） |

## 5. 架构
```
Apple Watch                                   iPhone
┌─────────────────────────────┐              ┌──────────────────────────────┐
│ UI：按钮/复杂功能/小组件      │              │ 接收 + 校验 + 回执             │
│ RecorderEngine（音频引擎）    │              │ 拼接（会话/段/中断标记）        │
│  ├ VADGate（音量门限）        │  分段文件     │ VAD 二次检测（FluidAudio）     │
│  ├ Encoder（Opus/AAC）        │ ───────────▶ │ 转写（WhisperKit / Parakeet） │
│  ├ Segmenter（定时换文件）    │  + 元数据     │ 说话人分离（FluidAudio）       │
│  └ InterruptionHandler        │ ◀─────────── │ 资料库（SwiftData）+ 搜索      │
│ SessionStore（状态落盘）      │   回执        │ 导出 Markdown / Obsidian      │
│ TransferQueue（排队/去重/重试）│              │ 可选 AI 摘要（用户密钥）        │
└─────────────────────────────┘              └──────────────────────────────┘
```

## 6. 开发任务与验收
| 编号 | 任务 | 验收标准 |
|---|---|---|
| T1 | 工程搭建：iPhone + Watch App、共享数据模型、设置存储 | 两端能安装运行，设置在两端同步 |
| T2 | 手表录音引擎：连续采集 + 分段写入 + 参数全部可调 | 改任一参数后录出的文件参数正确；段之间无缺口（拼接后时长误差 < 50ms） |
| T3 | 编码：Opus（或回退 AAC-HE）+ 抗中断容器 | 录音中强杀 App，已完成分段全部可播放；当前段可读出已写部分 |
| T4 | 静音跳过（音量门限 + 首尾保留） | 安静房间录 10 分钟只说 1 分钟话，存储显著小于不开时；话音首尾不被切 |
| T5 | 打断与崩溃恢复 | 录音中来电、唤起 Siri、强杀 App、重启手表，恢复后继续录或找回分段，时间线显示中断 |
| T6 | 开关入口：主按钮、复杂功能、小组件、操作按钮、iPhone 远程 | 每个入口 1 秒内开始录音并震动反馈 |
| T7 | 同步：边录边传、去重、校验、回执删除、断连续传 | 断开手机录 30 分钟，重连后全部到达且无重复；校验失败的段重传 |
| T8 | 手机端拼接 + 语音检测 + 转写（引擎可选） | 中文、英文各 10 段样本转写可用；切换引擎/模型档位生效 |
| T9 | 说话人分离 + 改名 | 2–4 人对话能分开；改名后全会话更新 |
| T10 | 时间线、播放跳转、搜索 | 点任意一句话跳到对应音频；关键词搜索命中所有会话 |
| T11 | 导出 Markdown / Obsidian、自动清理 | 导出文件含日期、时间戳、说话人；清理规则按设置执行 |
| T12 | 可选 AI 摘要（用户密钥） | 不填密钥时功能隐藏；只发送文字 |
| T13 | 隐私：数据保护、录音指示、首次提示 | 锁屏时文件不可读；录音中红点常显 |
| T14 | 实测与调参：各机型耗电、存储、转写速度 | 输出实测表，更新默认参数和“可录时长”估算 |
| T15 | 上架准备：隐私说明、麦克风权限文案、截图 | 通过 TestFlight 内测 |

## 7. 开工前必须先验证的问题
| 问题 | 为什么重要 | 验证方法 | 不行怎么办 |
|---|---|---|---|
| 手表能否用系统接口编码 Opus | 决定默认编码 | 真机测试音频转换器输出 Opus | 回退 AAC-HE 24 kbps，或集成开源 Opus 编码库（需评估许可证与耗电） |
| 抬腕/放下、熄屏后能否持续录音 | 核心体验 | 真机录 1 小时，期间熄屏、放下手 | 按苹果允许的后台音频方式调整；必要时提示保持 App 在前台 |
| Ultra 操作按钮能否绑定我们的 App 开始录音 | 开关体验 | 查官方接口并真机测试 | 只保留复杂功能和小组件入口 |
| 苹果系统语音识别的中文离线效果 | 是否可作为默认引擎 | 同一批样本与 WhisperKit 对比 | 默认用 WhisperKit |
| 说话人分离在中文对话上的效果 | 是否默认开启 | 用 2–4 人中文样本测试 | 默认关闭，手动开启 |
| 各机型录音耗电 | 设置页“可录时长” | T14 实测 | — |

## 8. 开发条件
- 一台 Mac + Xcode，至少一块 Apple Watch 和一部 iPhone 真机
- Apple 开发者账号（上架和 TestFlight 需要）
- 云端会话不能编译和真机调试手表应用：云端负责写代码、方案和测试用例，编译和真机测试在 Mac 上进行（可在 Mac 上开 Claude Code 会话接手）
