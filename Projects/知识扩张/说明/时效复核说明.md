# 时效复核任务（共享说明）

今天是 2026-10-28。AI 领域变化快。我们有一个学习资源目录，需要逐条判断每条资源**现在还适不适合拿来学**，过时的会从学习主题里拿掉（存档，不删除）。

## 判定标准（每条三选一）
- **适用**：内容仍与当前主流做法一致，可以照着学
- **部分过时**：主体仍有价值，但有具体章节/建议已被取代（必须写清哪部分过时、被什么取代）
- **已淘汰**：整体被新版本、新规范或新做法取代，或停更且内容已不符合现状（必须写清被什么取代；有新版本就给新版本链接）

判定原则：
- 只看“内容是否过时”，不看“对我们有没有用”
- 有新一期课程/新版规范时，旧一期标“已淘汰”并指向新一期（同一条目内已含新一期的除外）
- 停更但原理不变的（如方法论、新闻核查原则）可以是“适用”
- 没有足够证据时标“适用”并在 note 写“未发现过时证据（证据不足）”，不要臆测

## 已确认的证据（官方一手，可直接引用）
1. Anthropic《Best practices for Claude Code》（code.claude.com/docs/en/best-practices，2026-10 读取）明确列出以下旧建议“已不再适用”：
   - 把上下文窗口当主要约束、积极管理（现在多数模型 1M 窗口+自动压缩）
   - 给 Claude 总忽略的指令加 IMPORTANT 或全大写
   - 用子智能体来保护上下文窗口（子智能体仍适合并行、隔离噪声、独立评审）
   - 委派给子智能体能得到更好的答案
   - 在提示里写 think hard / be thorough（改用 effort 设置；ultrathink 仍有效）
   - 让 Claude “keep going / 不要偷懒”（改用可检验的检查或 Stop hook）
   - 在 CLAUDE.md 里描述架构和目录结构（Claude 会自己读仓库）
   同页还说：CLAUDE.md 建议 200 行以内；必须遵守的规则用 hook
2. Claude Code 文档（code.claude.com/docs/en/memory）：Claude Code v2.1.277 起可直接读 AGENTS.md（无 CLAUDE.md 时）
3. MCP 规范 2026-07-28 版：无状态化、多轮请求、收紧 OAuth；**Roots、Sampling、Logging 被标为弃用**。只讲旧规范或这三项的课程至少“部分过时”
4. Microsoft MCP for Beginners 2026-09-09 已按 2026-07-28 规范更新
5. CS146S：2026 秋季版已替换约 85% 的 2025 秋季内容（二手）；目录条目 K-001 已同时含两版

## 网络限制
- WebSearch 可用；WebFetch 大多数站点被拦，被拦一次就别再试同站。code.claude.com 可以 fetch
- 公共 GitHub 仓库可 `git clone --depth 1` 到 <草稿目录>/clones/ 下新目录（只读，不运行代码）；已有克隆可直接看（`git log -1 --format=%ad` 看最后更新）
- 每条最多 1–2 次搜索；能从已知证据或已有克隆判断的不要再搜。总搜索 ≤ 20 次

## 输出
JSON 数组写到指定文件，每个元素：
{"id":"K-0xx","currency":"适用|部分过时|已淘汰","note_zh":"一两句依据","outdated_parts_zh":"部分过时时写具体哪部分；否则 null","superseded_by":"取代它的东西（目录 ID 或名称+链接）；否则 null","evidence":"一手/二手 + 链接或来源","last_updated":"能查到的最近更新日期或 null"}
最后用 3–5 句话回复：各类各几条、最重要的过时发现、哪些证据不足。
